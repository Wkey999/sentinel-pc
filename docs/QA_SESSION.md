## 3. 已发现的交接问题

1. **长报告导出预览的按钮越界**：报告内容撑开布局，默认窗口内复制/下载按钮不可见。应限制预览正文高度并允许正文滚动，操作区保持可见；需重新封包实测鼠标与键盘操作。
2. **真实/演示文案冲突**：真实采集完成后，侧栏仍显示“桌面原生（合成预览）”，覆盖状态仍叫“样本可用”。应按 backend capabilities 与报告 provenance 显示。
3. **部分完成被过度表达为完成**：报告为 completed_partial，聊天工具六项仍全显示 Complete，文案为“本机真实扫描已完成”。应把“套餐执行结束”与“数据未覆盖”明确区分。
4. **能力宣称超过已实现范围**：计划提到 WHEA/热降频，当前套餐热传感器明确 unsupported；XMP/EXPO 和通道也不是已测得。提示应与实际 source/coverage 相符。
5. **取消入口未接通前端**：当前源码服务层没有调用 `cancel_run`，页面未见取消按钮。后端取消/未完成规则有自动化覆盖，但不能将其算作桌面取消流程通过。
6. **失败状态契约回放已确认**：24 个合成环境的 Rust 规则全部通过，但前端 Zod 只接收 21 个。timed_out、collection_failed、cancelled 三个环境因 coverageSchema 不接受 failed/timed_out/cancelled 被拒绝。失败位置是 report.coverage[*].status。这是当前源码的契约回放结果，不是对封包 EXE 强制造出这些硬件故障。

本轮完整源码回归：95 项 Rust 测试通过（另有 1 项 opt-in 真机测试默认跳过），24 项 TypeScript 测试与类型检查通过。新增实验室补出了原回归未覆盖的三类契约缺口，故实验室整体退出码为 1，而非全绿。

本机独立采集记录：Windows build 26300.9457、普通用户进程（非管理员）；显示、刷新率、内存、电源、系统卷五类来源 available，PCIe/热传感器 unsupported。完整输出见 `private-reports/test-lab/20261114-000048-29e65d/TEST_REPORT.md`。

## 5. 用户怎样重复测试

在项目目录双击 **运行测试实验室.cmd**，运行 24 个模拟环境和一次真实只读采集。初次需用已有本地 Rust/Node 工具编译测试示例，后续可以复用编译缓存。

也可在项目目录运行：

```powershell
# 仅合成环境，不读本机硬件
powershell -NoProfile -File scripts/test-lab.ps1

# 加入一次本机只读采集
powershell -NoProfile -File scripts/test-lab.ps1 -Live

# 完整源码回归 + 合成场景 + 本机采集
powershell -NoProfile -File scripts/test-lab.ps1 -Live -Full
```

每次生成独立目录 `private-reports/test-lab/<时间>-<随机后缀>/`，不会复用上轮真实报告充当本轮结果。最新报告路径写在 `private-reports/test-lab/LATEST.txt`。目录默认已被 Git 忽略。

- `TEST_REPORT.md`：中文汇总、24 场景结果、失败原因、真实覆盖和限制。
- `scenarios.json`：真实 Rust 规则输出并明确标注 synthetic 的场景结果。
- `contract-results.json`：用当前前端 Zod 校验每个返回值的结果。
- 每个场景的 `.md`：可读模拟报告。
- `live-report.md/json`：只有加 `-Live` 才有的脱敏真实采集。
- `rust-tests.txt`、`typescript-tests.txt`：只有 `-Full` 才运行的源码回归日志。

退出码为 1 表示发现失败项或测试运行错误，应查看报告和日志，不能写成“全部通过”。模拟输入不是封包 EXE 的导入格式，不要将这些 JSON 当成真实硬件报告导入生产案例。
