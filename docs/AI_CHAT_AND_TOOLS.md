# AI 问答与外部工具补证

实现日期：2026-11-14。本文区分已接通的链路与尚未完成的真机/API 验收。

## AI 问答

普通输入直接进入独立 `send_chat`，不再把所有问题当作故障问诊，也不再用已存报告摘要代替回答。首页预设场景和一键体检仍走原有只读诊断流程；正在回答问诊问题时，输入属于当前问诊答案。

链路：React 输入 → Rust 读取本机对话历史与所选案例 → 脱敏、裁剪上下文 → 已配置的 Chat Completions 服务 → 校验回复 → SQLite 保存 → 显示来源。默认使用现有 DeepSeek HTTPS 地址，沿用用户配置的模型和 DPAPI 凭据；旧 `sentinel-json-v1` 不冒充支持普通聊天。

2026-11-14 所有者调整提醒频率：普通 AI 问答前 10 次直接发送，第 11 次发送前提示服务、模型、费用归属和数据范围；继续后重新计数，每 10 次提醒一次。按已配置模型时发起的问答发送次数计数（请求失败也计一次），未配置模型不计数；暂不发送不重置计数。计数仅保存在本机 localStorage，跨对话和重启保留，桌面与浏览器预览分开；存储不可用时保留当前进程计数。打开软件、打开报告和完成体检不会自动发送模型请求。

模型收到：主动输入的消息、最近最多 6 轮成功对话、硬件缓存的采集时间及关键设备字段、当前案例的问题描述/时间范围、报告中的发现/体检项目/未知项。不会上传原始日志、报告附件或凭据。硬件来自缓存，并不代表实时传感器；缺数据须回答未知。上下文超限返回明确错误，不静默替换为演示数据。

跨对话本机事实：新对话也会从 SQLite 中读取最近完成的本机 `setup_audit`（按报告时间选取，包含旧轮次，排除合成/仅导入来源与失败/取消轮次），通过 `machineFacts` 提供检查摘要、来源时间及逐屏刷新率。不会附上其他案例的症状、聊天原文或附件。未完成的新复测不会抹去上轮已知值，删除对应案例后不再引用其记录。发送许可会说明这一范围。

例如上次体检保存了 280Hz，且当次同分辨率模式中未见更高值，后续新对话应直接引用这条事实，说明它是上次采样与已识别模式的比较；不能只因基础硬件概览没写刷新率就要求再次检查。聊天发送本身只读已保存记录和硬件缓存，不主动重跑采集。过时的值标明时间；用户明确询问实时状态、设备/接线/设置发生变化或确实缺该字段时，再建议刷新。

工程限制：单条消息 4000 字；模型历史最多 12 条并受 24 KiB 预算约束；完整模型输入 96 KiB，HTTP 请求 128 KiB；模型回答最多 12000 字，HTTP 响应 64 KiB；网关 45 秒等待，单并发，不自动重试。首版使用非流式请求，显示完整模型答复，不宣称 token 实时流式输出。

未配置、未许可、网络失败、服务拒绝、限流、截断、工具调用等均有明确提示，标记为 `unavailable`；失败提示不进入后续模型历史。只读体检仍可离线使用。模型没有工具执行入口，文字建议不会触发设置修改、安装程序或烤机。

存储：同一 `metadata.sqlite` 新增 `conversations` 表，不修改旧案例体；消息原文仅保存在本机（不是加密聊天库）。普通对话单列在“最近对话”，不生成体检案例；案例内追问绑定案例并随案例删除。每段对话最多保存 100 轮，模型只接收最近窗口；侧栏最多列最近 100 段普通对话。关闭重开后可从侧栏恢复，删除需确认。

新增 IPC（主窗口专用，DTO 拒绝未知字段）：

| 命令 | 请求 / 返回 |
| --- | --- |
| `send_chat` | `{conversationId, caseId: UUID 或 null, message, hardware: HardwareSnapshot 或 null, allowModel}` → Conversation |
| `get_chat` | `{conversationId, caseId}` → Conversation；未保存时返回空会话，不创建数据库记录 |
| `list_chats` | 无请求 → 普通对话摘要，messages 为空；案例聊天从案例入口加载 |
| `delete_chat` | `{conversationId}` → null |

Conversation 为 `{id,caseId,title,messages,updatedAtUtc}`，messages 为 `{role,text,origin}`。原生来源为 user/model/unavailable；browser_preview 仅供浏览器界面演示，不能宣称模型已调用。

## 体检缺口与工具

“待补证”保留后端 `unknown` 语义。不是所有未知都由权限引起：当前采集器没有可靠的实际内存通道、BIOS XMP/EXPO 开关、PCIe 上限与链路采样、通用 CPU/GPU 传感器读取。提升权限不保证补齐。它们不能标绿，也不能据此要求用户重插显卡、开启超频或清灰换硅脂。

| 工具 | 当前接入程度 |
| --- | --- |
| smartctl | 本机发现、受控只读后端、JSON 导入；外部查询独立授权 |
| CrystalDiskInfo | 本机发现、文本导入 |
| HWiNFO | 本机发现、英文 CSV 传感器日志预览解析与规则分析 |
| CPU-Z / GPU-Z | 本机文件发现、官方入口、手动补查说明；没有自动解析其报告 |
| OCCT | 本机文件发现、官方入口、手动压力测试说明；不自动启动、不自动读结果 |
| PresentMon | 规划项，未接入解析或采集 |

默认安装路径和用户指定工具箱均可发现文件。工具箱扫描最多 3 层子目录、2000 个条目，不跟随重解析点；只按已知文件名、PE 签名及哈希发现候选，不把存在性当成可信来源。命令执行仍只接受既有 smartctl 能力令牌；不会因为发现 OCCT 就授予运行权限。不捆绑、自动下载或安装这些软件。

压力测试由用户单独选择，先保存工作，监控温度并能随时停止；不加入 R0 一键体检。日志中出现限制标志也不直接证明散热器坏了或电源额定功率不足。

## HWiNFO CSV 使用与支持范围

1. 从 [HWiNFO 官方网站](https://www.hwinfo.com/) 获取软件，在 Sensors 窗口手动开启传感器日志，记录正常使用或问题出现时的情况，再停止记录。
2. 在哨兵“工具与来源”选择“HWiNFO 英文传感器 CSV（预览）”，选择本地文件。
3. 查看本地分析范围，点击“同意并分析报告”。结果保存为独立“外部报告 · HWiNFO”案例，不覆盖原体检；取消文件选择会清理临时案例。

编码：UTF-8（可带 BOM），或带 BOM 的 UTF-16 LE/BE；不猜测 ANSI/混合编码。首两列为 Date、Time，逗号/分号分隔，支持带引号字段与十进制逗号。同名传感器按列号保留独立身份，不合并不同设备。

白名单列（完整英文列名）：`CPU Package [°C]`、`GPU Temperature [°C]`、`CPU Package Power [W]`、`GPU Power [W]`、`Core Thermal Throttling [Yes/No]`、`Core Power Limit Exceeded [Yes/No]`、`GPU Thermal Limit [Yes/No]`。其他语言、改名、其他单位/列名和不同版本布局可能无法识别，明确保留为未覆盖。日志时间只保留文件声明，不擅自换算为 UTC，也不认为与当前体检同时发生。

温度/功耗给出末值、记录最大值与有效样本数；不会只凭高温数值确诊过热。明确 Yes 标志生成“日志记录限制标志”的观察；全 No 仍不代表未记录时段、其他设备或全部硬件正常。空值、NaN、无效行不会被当成通过。

这是格式预览：合成 CSV/Mock 的自动化验证不能替代用户真实 HWiNFO 日志的格式验收，也不能确认日志中的硬件身份、负载与时间真实性。

## 验证与官方资料

自动化覆盖：模型传输 Mock 的当前问题/历史/本机上下文、许可与配置失败、脱敏、重启恢复与删除；CSV 的明确限制标志、温度不能单独确诊、同名列、引号/十进制逗号、缺失与无效值。没有在测试中调用付费 API、启动烤机或安装驱动。

当前回归：Rust workspace 109 项通过、2 项显式真机采集默认忽略；前端 58 项通过、1 项本机快照文件验收默认跳过。浏览器验证了普通问题不创建体检案例、恢复已有对话、连续追加问题、每十次发送提醒、当前案例传递，以及深绿色状态标签（实际样式：文字 RGB 7/85/47、字重 700、背景 RGB 234/242/255）。合成验收页为开发服务的 `/tests/ui/chat-preview.html`，不联网，不使用用户 Key；其回调模拟不能代替真实模型验收。

真实模型是否可用仍取决于用户配置的 Key、模型权限、额度和网络，需在桌面端同意发送后验收。
