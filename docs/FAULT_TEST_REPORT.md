# 四类故障测试记录

测试日期：2026-11-14。范围为首页四个故障入口。本轮增加测试与开发回放页，没有改变正式诊断逻辑。

## 已验证的部分

| 入口 | 合成输入 | 实际结果 |
| --- | --- | --- |
| 游戏黑屏 / 闪退 / 掉帧 | Display 4101、Application Error 1000、同应用同启动会话的 WER | 显示驱动恢复、应用崩溃、受限时间关联共 3 项观察；不认定显卡损坏 |
| 突然重启 / 死机 / 蓝屏 | Kernel-Power 41、系统 BugCheck 1001 | 保留两项事件观察；不据 41 认定电源损坏，不声称已分析转储 |
| 硬盘掉盘 / 卡顿 / SMART 告警 | 经真实解析器处理的 smartctl ATA 告警样本 | 出现存储告警及先备份的建议；不预测剩余寿命 |
| 办公卡死 / 外设间歇断连 | Application Hang 1002、设备错误码 43 | 无响应与设备异常两项观察；不直接认定发生物理断连 |

浏览器中逐个点击四个正式入口，完成 3 轮问诊，检查分类、三份回答、创建、重命名、计划、模拟批准、单次启动、轮询、Rust 报告显示。四条流程均通过。界面使用正式 `DiagnosePage`，但 IPC 传输由测试页替换；这不是 Windows 故障真机采集验收。

另回放 13 项对照输入，总计 **17 / 17 场景通过**：单纯掉帧无遥测、仅 41、WHEA、SMART 声明正常、Disk 157、驱动 10111、当前 PnP 正常、窗口外 TDR、错误 Provider、拒绝访问、超时、空日志、取消。无证据、缺口与取消均没有被说成电脑健康。重复证据 ID 被拒绝。

真实执行的 Rust 代码包含规则、报告解析、内存 SQLite 案例、计划批准和重复启动保护、报告落库、JSON/Markdown 导出、重命名与删除。样本先进入对应规则分支，再统一标注 `synthetic`；不会写入用户真实案例库或硬件缓存。

当前回归结果：前端 62 项通过、1 项默认跳过；Rust workspace 111 项通过、2 项显式真机采集默认忽略。

## 本次确认的能力缺口

1. **掉帧**：尚无 FPS / 帧时间采集；没有崩溃、TDR 或传感器记录时，无法定位单纯掉帧。
2. **掉盘**：目前没有 Disk 157 专用分析规则。测试保留事件原证据，结果不生成掉盘专用观察；不能把这个负例通过理解为已经支持掉盘诊断。
3. **蓝屏**：能解释系统事件，尚未解析 dump 来定位具体驱动或根因。
4. **间歇断连**：能看设备当前状态和所采集的相关驱动事件，尚无持续 USB 断连监测。当前快照正常不排除历史故障。
5. **真机与模型**：本轮没有制造蓝屏、拔盘、强制断电或烤机，也没有调用付费模型；未覆盖不同电脑/驱动/Windows 版本下的完整真实采集结果。

## 再次运行

在项目根目录执行：

```powershell
powershell -NoProfile -File scripts/test-fault-lab.ps1
# 同时跑 Rust workspace 与前端检查：
powershell -NoProfile -File scripts/test-fault-lab.ps1 -Full
```

每次使用独立内存数据库，报告保存在 `private-reports/fault-lab/<本次时间>/REPORT.md`，同目录包含结构化结果和日志。脚本不启动故障注入、不修改系统设置、不调用采集器。

开发服务器启动后，打开 `http://127.0.0.1:1420/tests/ui/fault-preview.html` 可以亲自回放四个入口。页面顶部明确标识合成故障；“清空测试会话”可重新选择入口。该开发页不打包进入正式桌面版。

`tests/fixtures/fault-contract.json` 是由 `cargo run -p sentinel-core --example fault_lab -- OUTPUT.json` 导出的前四个场景快照，保存完整 Rust 阶段对象。`tests/fault-contract.test.ts` 校验前端 Zod 契约及预期规则；`crates/sentinel-core/tests/fault_flows.rs` 重跑全部场景断言。新场景应先写期望，再生成快照。
